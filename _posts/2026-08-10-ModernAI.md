Artificial Intelligence (AI) has become part of our daily lives. Many of us use AI assistants such as ChatGPT, Claude, Microsoft Copilot, or Gemini to answer questions, write emails, summarize documents, or generate code.

Recently, we hear a lot of new terms like **AI model, AI tool, AI agent, AI system,** and **Agentic AI**. But what are they, and what are the main differences among them?

<!--more-->

![Modern_AI]({{ "/assets/image/modernAI.png" | relative_url }}){: width="500"}

Before looking at the formal definitions, let's start with a simple example.

Imagine that you want to plan a weekend trip to a nearby city. You open **Microsoft Copilot** and tell it:

> "Plan a two-day trip for me. I like good food and peaceful places, and my budget is $500."

At first, this sounds like a simple request. But to actually complete the task, several different things may need to happen.

The AI needs to understand what you are asking for, reason about possible options, find relevant information, and potentially use different tools to help create the plan.

This simple example can help us understand the differences between an **AI model, AI tool, AI agent, AI system,** and **Agentic AI**.

## 1. AI Model: the "brain"

Let's start with the **AI model**.

An AI model is a trained computational model that processes input and produces an output. For example, a large language model (LLM) can process text and generate a response.

An important thing to understand is that an AI model is **trained using data**.

During training, the model is exposed to large amounts of data, such as text, images, audio, or other types of information. Through training, the model learns patterns and relationships in that data. These learned patterns allow it to make predictions or generate outputs when it receives new input.

For example, a language model is trained on large amounts of text. When you ask it a question, it processes your input and generates a response based on what it learned during training and the context provided at that time.

In our travel example, the model might understand that:

* You want a two-day trip.
* You prefer good food.
* You prefer peaceful places.
* You have a $500 budget.

It can then generate suggestions for destinations, restaurants, activities, and an itinerary.

You can think of the AI model as the **"brain"** of an AI application. This is only an analogy: the model is not a human-like brain, and it does not independently decide what to do outside the system in which it is used.

Also, the information learned during training is not necessarily the same as current information. The model may not know the latest hotel prices, restaurant opening hours, or weather conditions.

It may therefore need other components to access up-to-date information or interact with the outside world.

## 2. AI Tool: the "hands"

Now imagine that the AI system can use different tools to help answer your request.

For example, it might have access to tools that can:

* Search the web for current information
* Look up maps and calculate travel times
* Check the weather forecast
* Search for hotels or restaurants
* Calculate the total cost of the trip

These are **tools** that an AI system or agent can use.

A tool provides a specific capability. It usually performs a particular operation rather than deciding what the overall goal should be.

For example, a hotel-search tool might receive a request such as:

> "Find hotels under $200 per night."

The tool performs the search and returns the results.

The AI model can then use those results when working on the larger task.

It is also worth noting that a tool does not necessarily need to contain AI. A calculator, database, map service, or weather API can all be used as tools by an AI system.

A simple way to think about it is:

> **AI Model = Brain**

> **AI Tool = Hands and senses**

The model provides the core AI capability, while tools allow the system to access information and interact with external services.

## 3. AI Agent: the "worker"

Now let's make the example more interesting.

Instead of asking the AI one question at a time, you give it a goal:

> "Plan my entire two-day trip within my $500 budget."

To accomplish this goal, an AI agent may need to decide what to do.

For example, it could:

1. Find suitable destinations.
2. Search for hotels within the budget.
3. Check restaurants that match your preferences.
4. Find peaceful places or activities to visit.
5. Check travel times between locations.
6. Calculate the estimated cost.
7. Create a two-day itinerary.
8. Review the plan and adjust it if necessary.

The important part is that the system does not simply generate one answer. It can **decide what actions are needed and use tools to carry them out**.

This is where the concept of an **AI Agent** comes in.

An AI agent is an AI-based system or component that can pursue a goal by deciding what actions to take and then taking those actions, often by using tools and maintaining information about the task's current state.

A traditional AI interaction might look like:

> **You ask → AI answers**

An agentic interaction is more like:

> **You give a goal → AI plans → AI acts → AI observes → AI adjusts → AI continues**

An AI agent commonly combines an AI model with capabilities such as:

* **Planning** — deciding what steps may be needed
* **Tool use** — interacting with external tools and services
* **State or memory** — keeping track of relevant information and progress
* **Action** — doing something in the environment rather than only generating text

However, these should not be treated as a strict checklist. There is no single universally accepted architecture that every AI agent must follow. Different systems can implement agents in different ways. [1, 2]

## 4. AI System: the "whole machine"

So far, we have talked about the model, tools, and agent. But what connects all these pieces together?

This is where the idea of an **AI system** comes in.

An AI system is a broader system that uses AI models and potentially other components to perform a task or provide a service.

For our travel example, a simplified AI system might look something like this:

![AI_system]({{ "/assets/image/AI_system.png" | relative_url }}){: width="500"}

The **AI model** provides the core AI capability.

The **AI agent** uses the model to pursue a goal and decide what actions to take.

The **AI tools** allow the agent to interact with external information and services.

The **AI system** brings these components together, along with other components that may be needed, such as data, application logic, security, user interfaces, and monitoring.

Importantly, an AI system does not necessarily need to contain an AI agent.

For example, a simple chatbot can be an AI system that receives a question, sends it to an AI model, and displays the model's response. There may be no autonomous planning or multi-step action involved.

## 5. Agentic AI: a way of building AI systems

Finally, we come to **Agentic AI**.

Unlike an AI model or an AI tool, Agentic AI is not simply another component that we can point to in the system.

It is better understood as a **broader approach to designing AI systems in which AI has some degree of autonomy to pursue a goal**.

Consider two different ways of asking an AI to help with your trip.

In the first approach, you provide the instructions step by step:

> "Find three hotels."

Then:

> "Find five restaurants near those hotels."

Then:

> "Check the travel time."

Then:

> "Create a two-day itinerary."

Here, you are deciding most of the workflow.

In the second approach, you give the AI a higher-level goal:

> "Plan my two-day trip within a $500 budget. I like good food and peaceful places."

Now the system has more freedom to decide **which steps are necessary, which tools to use, and what to do next**.

This is the key idea behind Agentic AI:

> **Give the AI a goal, rather than specifying every step.**

The more autonomy an AI system has to plan, act, observe results, and adapt toward a goal, the more **agentic** its behavior can be.

Agentic AI does not necessarily require multiple agents. A single AI agent can operate in an agentic way.

However, some complex systems use multiple specialized agents that work together.

## 6. Multi-Agent System: a "team of workers"

Imagine that your travel-planning system has several specialized agents:

![Multi-Agent System]({{ "/assets/image/multiAI_system.png" | relative_url }}){: width="500"}

The **Hotel Agent** could focus on finding suitable accommodation.

The **Food Agent** could look for restaurants that match your preferences.

The **Activity Agent** could find museums, parks, and other peaceful places to visit.

A coordinator agent could then bring their results together and create the final itinerary.

This is an example of a **Multi-Agent System**, where multiple agents interact or coordinate to accomplish a task. [4]

A multi-agent system is therefore one possible way to build an agentic AI system. But **Agentic AI and Multi-Agent Systems are not the same thing**.

You can have:

> **One agent → an agentic system**

or:

> **Multiple agents → a multi-agent system**

Both can be part of an agentic AI approach.

## Putting everything together

Let's return to our original request:

> "Plan a two-day trip for me. I like good food and peaceful places, and my budget is $500."

We can now look at the different concepts behind this simple request.

| Concept                | Simple analogy   | Role in our example                                                             |
| ---------------------- | ---------------- | ------------------------------------------------------------------------------- |
| **AI Model**           | Brain            | Processes the request and generates or reasons about possible solutions         |
| **AI Tool**            | Hands and senses | Searches the web, checks maps, gets weather information, calculates costs, etc. |
| **AI Agent**           | Worker           | Uses the model and tools to pursue the travel-planning goal                     |
| **AI System**          | Whole machine    | Combines models, agents, tools, data, application logic, and other components   |
| **Agentic AI**         | Way of working   | Gives AI some autonomy to plan, act, observe, and adapt toward a goal           |
| **Multi-Agent System** | Team of workers  | Multiple agents collaborate or coordinate to solve a larger task                |

The boundaries between these terms are not always perfectly defined. Different researchers and companies may use the terms slightly differently.

But this simple mental model can help us understand how modern AI applications are being built.

The most important idea is that **an AI model is not the same thing as an AI agent**.

A **model** provides the core AI capability.

A **tool** provides a specific capability that an AI system can use.

An **agent** uses a model and tools to pursue a goal and take actions.

An **AI system** brings these components and other supporting components together.

And **Agentic AI** describes a broader approach in which AI systems can operate with some degree of autonomy rather than simply responding to every instruction one step at a time.

In other words:

> **Model → provides AI capability**

> **Tool → provides specific capabilities**

> **Agent → uses models and tools to pursue a goal**

> **System → brings everything together**

> **Agentic AI → gives the system more autonomy to achieve the goal**

Once we understand these basic building blocks, we can start to explore a more interesting question: **how do we actually build an AI agent?**
